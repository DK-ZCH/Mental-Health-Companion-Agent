## 2. 实现设计：`authorizedTargetUser` **不是**「管理员万能绕过」

按你的明确要求，管理员授权做成**具名操作登记**，而不是 `if (role == 管理员) return true;`：

```java
public enum AdminWriteOperation {
    UPDATE_APPOINTMENT("编辑咨询预约"),
    UPDATE_MESSAGE("编辑咨询留言"),
    UPDATE_FAVORITE("编辑咨询收藏"),
    UPDATE_ASSESSMENT_RECORD("编辑测评记录"),
    UPDATE_ASSESSMENT_DETAIL("编辑答题明细"),
    UPDATE_WRONG_QUESTION("编辑错题"),
    ADD_MESSAGE("提交咨询留言"),      // 批 3A 未发现管理端调用 → 登记仅为不破坏现状
    ADD_FAVORITE("提交咨询收藏")      // 同上
}
```

语义：**「当前操作者 + 具名业务操作 + 目标用户 → 是否被明确授权」**。
未登记的操作拿不到授权；新增管理端写入口必须在此**显式登记**；管理员路径带**审计日志**。

### 2.1 两个原语的规则

| 原语 | 用途 | 学生 | 管理员 | 心理老师 | 其他/null |
| --- | --- | --- | --- | --- | --- |
| `assertWritableTarget(request, 现有记录, studentId, counselorId)` | `/update`：这条**已存在的记录**我能不能改 | 仅当 `studentId == 自己`，否则**拒绝** | 放行（记录须存在） | **保持现状放行**（→ 批 4） | **拒绝** |
| `resolveWriteOwner(request, 具名操作, 提交的归属)` | 决定本次写入**落地的归属** | **强制为当前用户**（伪造值被忽略） | 保留其**显式目标**（未提交则不动该字段） | **保持现状**（→ 批 4） | **拒绝** |

> **为什么 `/update` 不能机械恢复注释**：管理端以动态 `${this.table}/update` 调用所有模块，
> 且表单含「请选择学生」选择器（批 3A §2.2）—— 若恢复成无条件覆盖，
> `管理员编辑 student 3` 会被改写成管理员自己的 id（B 类能力被误伤）。

> **为什么教师侧保持现状**：批 3A 结论 —— 「老师存在 `counselorId`」只能证明**数据关系**，
> 不能证明「老师可改任意学生的业务对象」。按「不凭空创造业务规则」，本批**不收紧**，登记至批 4。

`counselorId` 属批 3A 分类中的 **C 类（页面选择的目标老师）**，本批**保留客户端值**，与教师侧授权一并留待批 4。
