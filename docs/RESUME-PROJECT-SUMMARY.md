## 一、项目名称与定位

**心理健康管理平台 · AI 助手（Agent）能力建设** ｜ 独立项目

> 在既有 Spring Boot + Vue 心理健康管理平台上，为**学生**构建**受控可验证**的 Agent 能力：
> 9 个 Tool（7 只读 + 1 对受控写）、确定性安全兜底、统一 Tool 观测，
> 并以「单测 + 变异 + 真实 LLM 运行」三级证据收口。

**技术栈**：Java 17 · Spring Boot 3.5.16 · Spring AI 1.1.8（DeepSeek）· MyBatis-Plus · MySQL 8.0 ·
Vue 3 + TypeScript · Element Plus

## 二、详细版（推荐用于 1 页以上简历，6 条）

**1. Agent 身份域隔离（安全基线）**
设计 `(userId, userTable)` 二元身份并放入 `ToolContext`（不进模型视野），Tool 统一白名单校验、
域不符 **fail-closed**；咨询师/管理员在**调用模型之前**即被拒绝（HTTP 403），避免
「学生 id 与咨询师 id 都是 1」导致的跨角色串读。

**2. 只读 Tool 矩阵（7 个查询能力）**
覆盖测评记录、预约、留言、错题摘要、可咨询教师名录、测评趋势、收藏；
统一约束：SQL **字段白名单**（咨询师不载入 password/phone/email）、字典码→中文在**代码内确定性翻译**、
聚合/截断由代码完成并显式返回 `truncated`，不把统计与标签交给 LLM 猜。

**3. 确定性安全兜底（模型无关）**
实现 R/N 语义规则（意愿/否定生存/计划进行/自伤 + 否定/第三人称/纯讨论按**片段**排除），
由**服务端在模型回答之后追加**资源卡片 —— 卡片不在 Prompt 内，模型无法删除；
未配置真实资源时**不猜地区、不写 120、不编热线**，仅给无号码行为指引。

**4. 受控写操作：创建预约（本轮核心）**
两阶段「预览 → 确认」：预览只读校验并签发 **HMAC signed capability token**（uidHash、TTL 300s、动作绑定），
确认工具**无任何模型可控参数**（凭证由 HttpSession 草稿经 `ToolContext` 注入）；
写入前重新验签 + 重新校验，应用层查重负责业务语义，**数据库生成列唯一键**负责并发兜底
（`status=3` 通过 `NULL` 释放槽位）；并修复「客户端可自封 status」为创建强制待审核、更新仅允许 `1→2/1→3`。

**5. Tool 调用可观测性（统一包装）**
包装 `ToolCallback` 统一记录 **toolName / durationMs / success**，**刻意不记录**入参、返回值、异常消息与用户标识；
观测层 fail-silent（Recorder 异常不影响业务），但**工具异常原样抛出**（不吞、不改类型）。
通过 Spike 发现 Spring AI 1.1.8 的 `.tools()` **不接受** `ToolCallback`，改用 `.toolCallbacks()` 并通过契约测试锁定。

**6. 质量与证据链**
**299 个自动化测试**全绿；对关键规则做 **21 项变异实验**（如删签名/删用户绑定/删过期校验/删查重/
卸唯一索引/吞异常/日志带入参），逐项使对应测试转红；真实 LLM 端到端验证覆盖查询、安全兜底与
「预览→确认→真实写入」闭环；全程**零新增依赖、零前端改动**，仅 1 处 schema 变更（含回滚脚本）。

## 三、精简版（推荐用于 0.5 页，3 条）

- **受控 Agent 能力**：为学生构建 9 个 Tool（7 只读 + 1 对受控写）；二元身份 + 白名单 fail-closed，
  咨询师/管理员在调模型前即 403；身份只来自 `ToolContext`，模型无法指定。
- **确定性与受控写入**：安全兜底用「服务端后置追加」而非 Prompt；预约采用两阶段预览/确认 +
  HMAC capability token + Session 单条草稿 + 应用层查重 + **DB 生成列唯一键并发兜底**，
  并收敛「创建强制待审核、审核仅 `1→2/1→3`」。
- **证据链**：299 测试 + 21 项变异 + 真实 LLM 端到端；统一 `ToolCallback` 观测（仅工具名/耗时/成功），
  隐私字段零落日志；零新增依赖，1 处 schema（含回滚）。

## 五、❌ 禁写清单（写了会被追问穿）

| 不要写 | 事实 |
| --- | --- |
| 「支持多轮对话 / 实现 Memory」 | Agent 仍是**单轮无状态**；Session 只存「待确认预约草稿」 |
| 「RAG / 知识库问答」 | `knowledge_article` 仅 5 条 × 7 字符占位内容，**未做 RAG** |
| 「支持咨询师 / 管理员使用」 | **仅学生域**，其余角色在调模型前 403 |
| 「模型输出完全受控 / 号码已被禁止」 | 号码只是 **Prompt 软约束**，服务端仅保证「资源卡片不含号码」 |
| 「完整的线上监控 / APM」 | 只有结构化日志（tool 名/耗时/成功），无指标平台、无告警 |
| 「高并发 / 压测验证」 | 有唯一键并发兜底**设计**，但**无压测数据** |
| 「经真实用户验证」 | 全部为自测与探针 |

## 六、面试可主动提的两个「负分转正分」点

| 主动说明 | 加分理由 |
| --- | --- |
| 「这批只做了 1 个写操作，没有做取消/修改」 | 说明你**能守住批次边界**，不是功能堆砌 |
| 「确认流程仍依赖模型愿意调用无参工具，服务端只保证不误写」 | 说明你**分得清确定性边界与概率性约束** |

> 这两句比「我做了很多功能」更能体现工程判断。
