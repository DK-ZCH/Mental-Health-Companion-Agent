## 4. 语义差异的处理原则（**显式声明，不偷偷修**）

| # | 差异 | 处置 |
| :-: | --- | --- |
| **B1** | `String.valueOf(session.getAttribute("role"))` 缺失时得到**字符串 `"null"`**（非 `null`） | 收敛为真正的 `null`，并**先做三项结构化检查**证明等价（无 `role.equals(...)` → 不会 NPE；无 `"null"` 依赖；无外传）→ 定性为**已确认的语义收敛**，**不以「测试绿了」充当证明** |
| **B2** | `Integer.valueOf(String.valueOf(...))` 缺失时抛 `NumberFormatException`（500） | 统一为 **403 fail-closed** —— 后经用例 27 证明该状态**不可构造**，故属**潜在不一致**而非可达变更 |
| **B3** | `(Integer) session.getAttribute(...)` 缺失时得 `null` → MP 跳过字段 → **客户端归属值生效（潜在 fail-open）** | 同上：统一为 fail-closed |

> ⚠️ **重要**：B2/B3 的「不可达」结论来自**测试自身被 schema 挡下**（用例 27：`auth_token.user_id` NOT NULL → 无法构造「已认证但身份不完整」）→ 因此风险等级**主动降级**，未按初判描述为线上漏洞。
