## 四、若选 A：三个必须先裁定的设计问题

### Q1 · 写什么（范围）

| 选项 | 说明 | 风险 |
| --- | --- | --- |
| **A1 只做「创建预约」** | 单一操作，业务闭环最直接 | 日期/时段语义复杂，需校验 |
| A2 只做「收藏/取消收藏」 | 可逆、语义简单，最适合作为「第一个写操作」 | 业务价值偏低 |
| A3 两者都做 | 覆盖广 | 范围过大，不建议 |

**建议**：**A1**，但把「取消自己的预约」列为**明确不做**（删除风险高，且已有 UI）。

### Q2 · 确认机制（本轮最关键的裁定）

| 方案 | 做法 | 需 DB 变更 | 优点 | 风险 |
| --- | --- | :-: | --- | --- |
| **① 同会话两阶段（签名 token）** | 工具返回「草稿 + token」；用户回复确认后，模型带回 token，服务端验签 | ❌ | 零 schema | 模型可能丢失/改写 token；**token 经模型文本往返**，需严格验签 + 绑定 userId |
| **② 服务端草稿表** | 新建 `agent_pending_action` | ✅ | 最稳，天然单次消费 | 新增表（本项目至今零 schema 变更）|
| **③ Session 草稿** | 存 `HttpSession` | ❌ | 零 schema、无需模型带 token | 多标签冲突；会话过期即丢；服务重启丢失 |
| **④ 前端确认弹窗** | 工具只返回预览，前端二次确认后调既有端点 | ❌ | 体验最好、责任清晰 | **需前端改造**；且要新增「Agent 触发的前端确认」交互 |

**建议**：**①（签名 token）** 作为第一版 —— 零 schema、零前端改动，
但必须绑定 `userId + 内容摘要 + 过期时间`，并**显式接受**「模型可能丢 token」的体验缺陷（丢了就重新生成草稿，不产生副作用）。

### Q3 · 幂等与重复预约（存在真实缺口）

| 现状 | 风险 |
| --- | --- |
| 无唯一索引；`/add` 无重复校验 | 同一学生可对同一老师、同一日期、同一时段**重复提交多次** |

| 方案 | 说明 | 需 DB 变更 |
| --- | --- | :-: |
| a. 应用层查重 | 提交前查 `student_id + counselor_id + date + slot` | ❌（并发窗口仍可能重复）|
| **b. 唯一索引** | 数据库层兜底 | ✅ |
| a + b | 查重给友好提示 + 索引兜底 | ✅ |

**建议**：**a + b**。但 b 属 **schema 变更**，需你明确批准 —— 这是 Round 4 唯一的 DB 改动点。

> **🔍 取证已完成** → [`PHASE4-ROUND4-APPOINTMENT-MODEL-EVIDENCE.md`](./PHASE4-ROUND4-APPOINTMENT-MODEL-EVIDENCE.md)
> · 时间模型 = `appointment_date` + **字典槽（1–8，固定 1 小时）** ⇒ **无区间重叠**，重叠 ⟺ 同一 `(date, slot)`
> · `(counselor, date, slot)` **兼容现有数据**；`(student, date, slot)` **与现有数据冲突（student 1 同日同槽 2 条）⇒ 不可加**
> · 推荐 `UNIQUE(counselor_id, date, slot, active_guard)`，`status=3` 时守卫为 `NULL` ⇒ **拒绝后释放槽位**
> · 🔴 **前置条件**：`/add` `/update` 从不 `setStatus` ⇒ 学生可自封 `status=2`；**加索引会把该 P1 放大为「长期占槽」**
> ⇒ 因此唯一键的启用**依赖** `status` 最小修复（需你批准）

## 五、若选 A：候选验收矩阵（先设计，实施时展开）

```text
S1  预览阶段【不写库】           → 调用后 DB 记录数不变
S2  未确认 → 不写库               → 只返回草稿
S3  确认 → 恰好写入 1 条          → status=1(待审核)、studentId=本人
S4  token 被篡改/伪造 → 拒绝      → 不写库
S5  token 过期 → 拒绝             → 不写库
S6  重复确认（同一 token）→ 拒绝  → 仍只有 1 条
S7  重复预约（同老师+同日+同时段）→ 拒绝并说明
S8  过去日期 / 非法时段 → 拒绝    → 不写库
S9  咨询师不存在 → 拒绝
S10 counselor/admin 调写工具 → 拒绝（域白名单）
S11 模型无法指定 studentId        → 只能来自 ToolContext
S12 写入失败 → 不得谎报成功
```

**变异（证明测试非恒真）**：删确认校验 / 删重复校验 / 删日期校验 / 让 studentId 取自模型参数，
各自应使对应用例转红。
