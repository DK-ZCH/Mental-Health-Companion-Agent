# ⑦b-1 向量检索可行性 —— 对照实验设计（零代码 · 实验不接生产）

> **性质**：🧊 **实验设计 v1（零代码）· 待用户批准实验方案后才开始写实验脚本**
> **纪律（冻结）**：实验不接入生产链路；主工程 `pom.xml` **不引入** embedding/向量依赖；
> 实验代码（若批准）放独立目录 `experiments/step7b1/`，独立依赖清单，不进 Maven 构建。
> **目标**：回答一个问题 —— **向量检索能否改善 L2c 暴露的语义召回缺口**。能，才谈模型/成本/持久化。

---

## 一、实验假设与判读标准（先定义「什么算改善」）

| 项 | 内容 |
| --- | :-: |
| H0（原假设） | 向量检索与关键词检索在测试集上召回无显著差异 ⇒ **不立项**，缺口归因到「语料内容未覆盖该表述」（转 ⑥ 语料补充而非 ⑦b）|
| H1（备择） | 向量检索在**关键词零命中的同义 Query** 上召回目标文章，且**不引入新的跨域误检** ⇒ 改善证据成立，进入第二阶段（生产接入设计）|
| 判读 | 每条 Query 标注「期望文章」；关键词基线召回 vs 向量召回（topK=2）；核心指标 = **同义组召回率** 与 **跨域误检数** |

🔴 **可复现性要求**：embedding 输出随模型版本变化 ⇒ 实验固定 embedding 提供方与模型名，
结果记录模型名+日期；同批实验内可复现，跨期不承诺。

## 三、两条待对比的检索实现

| | 关键词基线（生产 ⑦a）| 向量候选（实验）|
| --- | --- | --- |
| 实现 | 词表路由 → topK=2（`KeywordKnowledgeRetriever`，已生产）| **实验脚本内**实现：12 篇正文切分（按篇，沿用 ⑥ 粒度）→ embed → 与 query embedding 余弦相似度 → topK=2 |
| 依赖 | 无 | 实验目录独立依赖（见 §四候选，**不进主 pom**）|
| 切分粒度 | — | **按整篇**（12 篇各 800–1200 字，接近 embedding 上限；不切分会稀释细节，切分策略列为实验变量，v1 按整篇最简）|
